# タロショット (Full)

**画像**を登録すると **Gemini API** でナレーションを生成し、**新規スライド**（画像全面＋スピーカーノート）を自動作成します。YouTube 動画用ナレーション・Google Vids 読み上げを想定しています。

**配布の主経路は Web アプリ**です（スライドのコピーや GAS 貼付は不要）。詳細な Web 化手順は `設計書_タロショット_Web化.md`。

- **画像**: PNG / JPEG。ファイル名の昇順がスライド番号になります（1.png → 1 枚目など）。
- **画像枚数**: アプリ側では上限を設けません（ただし Gemini の入力サイズ制限に当たる場合があるので、その場合は画像を圧縮するか枚数を減らしてください）。

---

## ウェブアプリのデプロイ（必須）

誤って「自分（オーナー）」実行にすると、利用者の Drive や API Key がオーナー側になります。**必ずアクセスしているユーザーで実行**する。

### 初回

1. リポジトリ直下で `clasp push -f`
2. GAS エディタ → **デプロイ** → **新しいデプロイ** → 種類 **ウェブアプリ**
3. **実行するユーザー**: ウェブアプリにアクセスしているユーザー
4. **アクセスできるユーザー**: 全員（Google アカウント）または組織内
5. **デプロイ**。表示された `/exec` URL が本番（マスターのリンクに使う）

### コード更新（URL を維持）

1. `clasp push -f`
2. **デプロイ** → **デプロイを管理**
3. 本番のウェブアプリを選び **編集（鉛筆）**
4. **バージョン** を **新しいバージョン** にする
5. **デプロイ**
6. **新しいデプロイは作らない**（URL が変わる）

### 更新前チェック

- [ ] 実行するユーザー = **ウェブアプリにアクセスしているユーザー**（「自分」ではない）
- [ ] 本番 URL が前回と同じ `/exec` である

## 必要なもの

- Google アカウント
- [Google AI Studio](https://aistudio.google.com/) で取得した **Gemini API キー**
- **画像用**と**スライド用**の **Google ドライブのフォルダ**（それぞれフォルダ ID を取得して使います）

## セットアップ

### 1. スライドにスクリプトを紐づける

1. 使いたい **Google スライド**を開く。
2. **拡張機能** → **Apps Script** を開く（スライドに紐付いた GAS プロジェクトが開きます）。
3. このリポジトリの `src/` 以下を GAS プロジェクトに反映する。
   - **clasp を使う場合**: リポジトリ直下で `clasp push`（`.clasp.json` の `scriptId` を GAS のスクリプト ID にしておく）。  
   - **手動の場合**: `src/` 内の各ファイル（Code.gs, Config.gs, DriveHelper.gs, Gemini.gs, SlidesHelper.gs, TaroshotDialog.html, Upload.html, appsscript.json）を GAS に追加または上書きする。
4. 詳細は **src/README_GAS.md**（clasp の使い方・スクリプトプロパティ・トリガーなど）を参照。

### 2. 初回だけ：ダイアログから設定を登録

1. スライドを開き直すとメニューに **「タロショット」** が表示されます。
2. **タロショット** → **タロショットを開く** でダイアログを開く（初回は権限の許可が出る場合があります）。
3. **左側「1. システム情報設定」**
   - **Gemini API Key**: AI Studio で取得した API キーを入力。
   - **Google ドライブ ID 画像用**: 画像を置くフォルダの ID を入力。  
   - **Google ドライブ ID スライド用**: スライド（と一時的に JSON）を保存するフォルダの ID を入力。  
     （いずれもフォルダを開いたときの URL の `folders/` の後ろの文字列）
4. **登録** を押すと、これらの値がスクリプトプロパティに保存され、「データ保存済」と表示されます。

以降は、同じスライドを開けばメニューからダイアログを開くだけで利用できます。

---

## 使い方（ダイアログ）

1. スライドを開く → メニュー **タロショット** → **タロショットを開く**。
2. **左側**で API キーと「画像用」「スライド用」の 2 種類のドライブ ID を入力して **登録**（初回または変更時のみ）。
3. **右側「2. スライド生成」**
   - **1. 画像登録**: クリックしてローカルの画像ファイルを選択。  
     - **画像用フォルダ**の中身は**いったんゴミ箱に移動**されたあと、選択した画像がアップロードされます。  
     - 進捗は「処理中… N/枚数」「完了: N 件をアップロードしました。」で表示されます。
   - **2. スライド生成**: クリックすると、画像を読み込み → Gemini でナレーション生成 → 新規スライド作成。  
     - 「画像を読み込み、ナレーションを生成中…」「スライドを作成中…」と表示され、完了すると **スライドが自動で新規タブに開き**、「スライドを新規タブに表示しました！」と表示されます。
   - **3. スライド表示**: 直前に生成したスライドの URL を、もう一度開きたいときにクリックします。

## オプション機能

### トリガーで自動実行（runImageToJson）

画像フォルダにすでに 1.png, 2.png … を置いてある場合、GAS の **トリガー** で **runImageToJson** を時間主導で実行できます。実行ログで完了と保存先を確認できます。

### 画像アップロード用 Web アプリ（Upload.html）

**デプロイ** → **ウェブアプリ** としてデプロイすると、ブラウザで開ける URL が発行されます。その URL から画像を選択して「画像フォルダへアップロード」すると、スクリプトプロパティの `IMAGE_FOLDER_ID` で指定したフォルダに保存されます。  
（ダイアログの「1. 画像登録」を使わず、別経路で画像を入れたい場合に便利です。）

## プロジェクト構成（src/）

| ファイル | 説明 |
|----------|------|
| **Code.gs** | メニュー追加・ダイアログ表示、設定保存/取得、画像フォルダクリア、画像保存、スライド生成 Step1/Step2、Web アプリ doGet、runImageToJson（トリガー用） |
| **Config.gs** | 定数（Gemini モデル、画像枚数上限、スクリプトプロパティのキー名など） |
| **DriveHelper.gs** | 画像フォルダからのファイル取得、base64 取得、JSON 保存 |
| **Gemini.gs** | ナレーション用プロンプト、Gemini API 呼び出し、JSON パース・リトライ |
| **SlidesHelper.gs** | ナレーション JSON から新規スライド作成、スピーカーノート設定 |
| **TaroshotDialog.html** | タロショット用モーダルダイアログ（設定・画像登録・スライド生成の UI） |
| **Upload.html** | 画像アップロード用 Web アプリの画面 |
| **appsscript.json** | タイムゾーン、OAuth スコープなど（`script.container.ui` でダイアログ表示を許可） |
| **README_GAS.md** | clasp での push、スクリプトプロパティ、トリガー、Web アプリデプロイの詳細 |

## 注意事項

- 画像は **全枚を 1 リクエスト** で Gemini に送ります。枚数が多いとサイズ制限に当たる場合があるため、必要に応じて画像を圧縮するか枚数を減らしてください。
- 「1. 画像登録」では、**画像用フォルダ**内のファイルを **ゴミ箱に移動**してからアップロードします。必要なファイルはフォルダに残さないでください。
- スライド用フォルダには、スライド作成時に一時的に JSON が保存されますが、**スライド作成完了後にその JSON はゴミ箱に移動**されます。スライドファイルはフォルダに残ります。
- API キーはログ・エラーメッセージに出力しないよう配慮しています。
