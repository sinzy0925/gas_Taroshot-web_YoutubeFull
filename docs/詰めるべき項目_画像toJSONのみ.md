# 画像→Groq→JSON まで（GAS）の詰めるべき項目

**スコープ**: 画像ファイルを Google ドライブ経由などで取得 → Groq API に送る → 説明文の JSON ファイルを作る／保存する、までのみの GAS アプリを想定。

---

## 確認結果：提案採用済み・実装開始可

- **結論**: 提案どおり採用し、**設計方針を `設計方針_画像toJSON_GAS.md` にまとめた。実装を開始できる状態です。**
- **採用した方針**
  1. **バッチ数**: 5枚/回で固定。
  2. **入力経路**: トリガー実行のみ。画像は Drive の指定フォルダ（Script Properties の `IMAGE_FOLDER_ID`）に 1.png, 2.png... を事前に置く。
  3. **API キー**: トリガー運用のため Script Properties（`GROQ_API_KEY`）に保存。Logger・エラーメッセージには出力しない。
  4. **エンドポイント・モデル**: Script Properties の `GROQ_API_URL` / `GROQ_MODEL` で変更可能。未設定時は既定値を使用。
- **設計ドキュメント**: 詳細は **`設計方針_画像toJSON_GAS.md`** を参照。

---

## 1. 画像の取得方法

| 項目 | 詰めること | 内容 |
|------|------------|------------|
| **入力経路** | 「Google ドライブ経由」のみか、Web からのアップロードも併用するか。 | Web からのアップロードも併用 |
| **Drive の場合の指定方法** | フォルダ ID を指定するか、ファイル ID のリストを指定するか。または「このフォルダ内の画像を 1.png, 2.png の順で使う」ようなルール（名前順・更新日順など）をどう決めるか。 | drive フォルダID（共有済）にローカルのフォルダに置いた、1.png 2.png ... をアップロードしたい　|
| **ファイル名と slideNo の対応** | 仕様の「1.png → slideNo:1, 2.png → slideNo:2」を満たすため、取得した画像の並び順をどう決めるか（ファイル名の昇順、作成日順、ユーザーが並べ替え可能にするか など）。 | ファイル名の昇順 |
| **画像の最大枚数** | 上限を何枚にするか（例: 20 枚固定、または 50 枚までなど）。Groq は 1 リクエスト最大 5 枚なので、枚数が増えるとバッチ数が増え RPM を消費する。 | 最大50枚（一旦きめるが、そんなに増えない）
| **対応画像形式** | PNG / JPEG のみか、他（WebP 等）も許可するか。Groq の仕様（1枚 20MB やリクエスト合計 4MB 等）に合わせる。 | png / jpeg のみ |
| **画像のサイズ・容量** | アップロード前にリサイズ／圧縮するか。Groq の制限（1リクエスト合計 4MB 等）を超えないようにする方針を決める。 | そうします |

## 2. Groq API 呼び出し

| 項目 | 詰めること |
|------|------------|
| **API キーの扱い** | Script Properties に保存するか、毎回ユーザー入力（保存しない）か。 | **採用**: トリガー運用のため Script Properties に保存（`GROQ_API_KEY`）。 |
| **エンドポイント・モデル** | Groq の OpenAI 互換 URL とモデル名を定数で持つか、設定で変えられるようにするか。 | **採用**: Script Properties に `GROQ_API_URL` と `GROQ_MODEL` を保存。未設定時は既定値（同上）を使用。GAS「プロジェクトの設定」→「スクリプト プロパティ」で変更可能。 |
| **1 回のリクエストに含める画像数（バッチ）** | 1 / 2 / 3 / 4 / 5 のどれをデフォルトにするか。ユーザーが選べるようにするか、固定（例: 5 枚で 1 回）にするか。 | **提案**: 5枚/回で固定（未記入のため実装時この案で進める。変更希望あれば指定可）。 |
| **並列度** | 複数バッチを同時に送るか、1 本ずつ順番に送るか。RPM（例: 30）を超えないように並列数を決める。 | デフォルトは、RPMの半分 |
| **画像の送り方** | base64 で本文に含めるか、URL で渡すか。GAS からは Drive の画像を base64 に変換して送る形が現実的。URL の場合は「公開リンク」が必要になるかどうかも決める。 | base64 |
| **プロンプトの置き換え** | プロンプト内の「1.png〜20.png」「slideNo は 1～20」を、実際の枚数（例: 12 枚）に合わせて動的に変えるか、固定文のままにするか。 | 動的 |

---

## 3. JSON の生成・保存

| 項目 | 詰めること |
|------|------------|
| **複数バッチのマージ** | 5 枚ずつ 4 回呼んだ場合、返ってきた 4 個の JSON を 1 つの `{ "version": 1, "slides": [ ... ] }` にマージするルール。slideNo の連番がずれないようにする。 | はい |
| **レスポンスのパース** | Groq が ```json ... ``` で囲んで返した場合の取り除き方。正規表現でブロックを削除してから `JSON.parse` するか。 | はい |
| **JSON の保存先** | （ア）同じ GAS プロジェクトの Drive の「指定フォルダ」に新規ファイルとして保存する、（イ）Google ドキュメントに貼り付ける、（ウ）Script Properties には入れず、返り値や Web 画面にだけ表示してユーザーがコピーする、のどれ（または組み合わせ）にするか。 | ア |
| **保存時のファイル名** | 例: `マニュアルJSON_2025-03-10 12-00.json` のように日時入りにするか、固定名で上書きするか。 | 日付つき |
| **保存先フォルダ** | 保存する場合、フォルダ ID を Script Properties で持つか、実行時に指定させるか、マイドライブのルートか。 | フォルダIDを設定します |

## 4. UI・起動方法

| 項目 | 詰めること |
|------|------------|
| **起動方法** |  doGet で Web アプリ（HtmlService）として「画像指定＋説明文生成」画面を出すか、サイドバー／ダイアログで Drive フォルダを選んで実行するか、トリガーで定期実行するだけか。 | トリガーで定期実行するだけ |
| **画像指定の UI** | Drive 経由なら「フォルダ ID を入力」「フォルダをピッカーで選択」のどちらか。 | **採用案**: トリガー実行のみなら「画像フォルダID」を **Script Properties** に事前設定。実行時にそのフォルダ内の 1.png, 2.png...（名前昇順）を読む。 |
| **進捗・結果の見せ方** | 実行中は「処理中です」だけか、バッチ単位で「4/4 リクエスト完了」のように出すか。結果は「JSON を画面に表示」「Drive のリンクを表示」「ダウンロード用 blob リンク」のどれにするか。 | 実行中は「処理中です」だけ。トリガー実行なら **Logger.log** で進捗・完了時は保存先 Drive リンクを出す。 |
| **バッチ数の選択** | 「1 回の API で何枚送るか」を画面のドロップダウンで選ばせるか、コード内の定数で固定するか。 | デフォルトの並列数と同じ |

---

## 5. エラー・制限

| 項目 | 詰めること |
|------|------------|
| **429（RPM/TPM 超過）** | レスポンスの `retry-after` を見て待ってから再送するか、エラーメッセージを出してユーザーに「しばらく後に再実行」を促すだけにするか。 | エラーメッセージのみ |
| **API エラー・ネットワークエラー** | ログに残すか、画面に短いメッセージを出すか。キーをログに出さないようにする。 | ログに出す |
| **部分失敗** | 4 バッチ中 2 バッチ目だけ失敗した場合、1 バッチ目だけ反映した JSON を返すか、全体を失敗扱いにして何も返さないか。 | 全体を失敗扱い |
| **画像が 0 枚・1 枚** | 0 枚のときは実行しない／エラーにする。1 枚だけのときも同じプロンプト・形式で 1 スライド分の JSON を返すか。 | 0枚以外は実行 |
| **レスポンスが JSON でない** | パースに失敗したとき、リトライするか、そのバッチをスキップしてエラーとして報告するか。 | パース失敗時はリトライ　その他はエラー　|

---

## 6. セキュリティ（仕様どおり厳格にする場合）

| 項目 | 詰めること |
|------|------------|
| **API キー** | 画面で入力する場合は type=password、URL/Referer に含めない。GAS に渡す場合は Logger やエラーメッセージに出力しない。 | はい |
| **HTTPS** | Web アプリとして公開する場合は「テスト」ではなく「本番」で HTTPS で配信する前提にするか。 | はい |
| **キー保存** | 保存しない方針なら、毎回入力。保存するなら Script Properties に限る等、保管場所を決める。 | **採用**: トリガー運用のため Script Properties に保存。 |

---

## 7. 実装前に決めておくとよい一覧（優先度）

- **必須に近い**: 画像の取得方法（Drive フォルダ ID かファイル ID リストか）、並び順、最大枚数、バッチ数（1～5）、JSON のマージルール、レスポンスのコードブロック除去、JSON の保存先（Drive ファイル or 画面表示のみ）。
- **あるとよい**: API キーは保存するか毎回入力か、429 時のリトライ方針、部分失敗時の扱い、プロンプトの枚数（1.png〜N.png）の動的置換。
- **後回しでも可**: バッチ数の UI 選択、進捗表示の細かさ、保存ファイル名規則、フォルダ ID の指定方法（固定 vs 入力）。

以上を決めれば、「画像（Drive 等）→ Groq → JSON ファイル」までだけの GAS アプリの仕様として固められます。
