# 設計方針：画像→Gemini API→JSON（GAS・トリガー実行版）

**スコープ**: Drive の指定フォルダ内の画像（1.png, 2.png ...）を読み、**Gemini API** で**ナレーション原稿のみ**を生成し、JSON を指定フォルダに保存する。**YouTube 動画用**（Google Vids 等で読み上げに利用）。**全画像を 1 リクエスト**で送り、Gemini 2.5 Pro Preview / 3.1 Pro Preview で 1 実行で完了。各スライドは `slideNo` と `narration` のみ出力。

**参照**: 仕様・詰め項目は `詰めるべき項目_画像toJSONのみ.md`。

---

## 1. 全体フロー

1. **トリガー**でエントリポイント関数を実行する。
2. **Script Properties** から設定を読む（画像フォルダID、保存先フォルダID、GEMINI_API_KEY、任意で GEMINI_MODEL）。
3. 画像フォルダ内の **PNG/JPEG** をファイル名昇順で取得（最大 50 枚）。0 枚ならエラーで終了。
4. **全画像を 1 回の Gemini API 呼び出し**で送る。プロンプトは枚数（1～N）に合わせて動的。`generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` を REST で呼ぶ。
5. レスポンスから **コードブロックを除去**して `JSON.parse`。**パース失敗時はリトライ**。それでも失敗なら全体を失敗扱い。
6. `slides` を slideNo でソートし、**1 つの `{ "version": 1, "slides": [ ... ] }`** として保存。
7. **保存先フォルダ**に、**日付付きファイル名**（例: `ナレーションJSON_2025-03-10_12-00.json`）で新規ファイルとして保存。
8. **Logger.log** で「完了。スライド N 件。保存先: URL」を出す。

---

## 2. 設定（Script Properties）

| キー | 必須 | 説明 | 例 |
|------|------|------|-----|
| `GEMINI_API_KEY` | ○ | Gemini API キー（Google AI Studio で取得） | （ユーザーが設定） |
| `IMAGE_FOLDER_ID` | ○ | 画像を置く Drive フォルダ ID（1.png, 2.png ... を置く） | |
| `OUTPUT_FOLDER_ID` | ○ | JSON を保存する Drive フォルダ ID | |
| `GEMINI_MODEL` | × | モデル ID。未設定時は既定値を使用 | `gemini-2.5-pro-preview` |

- API キーは **Logger・エラーメッセージに出力しない**。
- 未設定の必須キーがあったら **起動時にエラー** とし、処理を開始しない。

---

## 3. 定数・数値（コード内）

| 項目 | 値 | 備考 |
|------|-----|------|
| 画像の最大枚数 | 50 | 上限。超過分は無視するかエラーにするかは実装で決定 |
| 対応画像形式 | PNG, JPEG | 拡張子または MIME で判定 |
| 1 リクエストあたりの画像数（バッチサイズ） | 5 | Groq の上限いっぱい |
| 並列度 | RPM の半分 | 例: RPM=30 なら 15。RPM は定数（例: 30）で持つ |
| 1 リクエスト合計サイズ上限（目安） | 4MB | 超える場合はリサイズ／圧縮してから送る |
| パース失敗時のリトライ回数 | 例: 2 回 | 定数で持つ |
| パース失敗時のリトライ間隔 | 例: 3 秒 | `Utilities.sleep(3000)` 等 |

---

## 4. 画像の取得

- **対象**: `IMAGE_FOLDER_ID` のフォルダ直下のファイルのうち、拡張子が `.png` / `.jpg` / `.jpeg`（大文字含む）のもの。
- **並び順**: **ファイル名の昇順**。これが 1.png → slideNo:1、2.png → slideNo:2 の対応になる。
- **枚数**: 最大 50 枚。0 枚のときはエラーとして終了（Logger にメッセージ）。1 枚以上なら実行する。
- **リサイズ／圧縮**: 1 バッチ（最大 5 枚）の合計が 4MB を超えないようにする。実装では「長辺を 1024px に制限」「JPEG 品質 85」など、定数で方針を決める。

---

## 5. Groq API 呼び出し

- **方式**: `UrlFetchApp.fetch` で OpenAI 互換の `chat/completions` に POST。画像は **base64** で `content` 内の `image_url`（`data:image/xxx;base64,...`）で送る。
- **プロンプト**: `Googleスライド生成アプリ_groq.md` の「プロンプトスタート〜プロンプトエンド」をベースに、**実際の枚数 N に合わせて動的に置換**する。
  - 「1.png〜20.png」→「1.png〜N.png」
  - 「slideNo は 1～20」→「slideNo は 1～N」
- **JSON mode**: 可能なら `response_format: { type: "json_object" }` を指定（Groq の仕様に合わせる）。
- **429**: リトライは行わず、**エラーメッセージを Logger に出す**だけで終了。
- **部分失敗**: いずれか 1 バッチでも失敗したら **全体を失敗扱い**。JSON は保存しない（または既存ファイルは上書きしない）。

---

## 6. JSON のマージ・パース・保存

- **マージ**: 各バッチのレスポンスは `{ "version": 1, "slides": [ ... ] }` の形を想定。複数バッチ分の `slides` を順に結合し、**slideNo が 1 から連番になるように** 1 つの `{ "version": 1, "slides": [ ... ] }` にする。
- **パース**: レスポンス文字列から \`\`\`json と \`\`\` で囲まれたブロックを除去（正規表現可）。その後 `JSON.parse`。失敗時はリトライし、それでも失敗ならエラーとして全体失敗。
- **保存**: `OUTPUT_FOLDER_ID` のフォルダに、ファイル名 `マニュアルJSON_YYYY-MM-DD_HH-mm.json`（JST）で新規作成。中身は UTF-8 の JSON 文字列。

---

## 7. エラー・ログ

| 状況 | 扱い |
|------|------|
| 必須 Script Properties 未設定 | 起動時にエラー。Logger に「GROQ_API_KEY が設定されていません」など（キーそのものは出さない）。 |
| 画像 0 枚 | Logger にメッセージを出して終了。 |
| 429（RPM/TPM 超過） | エラーメッセージを Logger に出す。リトライしない。 |
| API エラー・ネットワークエラー | ログに残す（キーは含めない）。全体を失敗扱い。 |
| パース失敗 | リトライ後も失敗なら全体を失敗扱い。 |
| 部分失敗（一部バッチのみ失敗） | 全体を失敗扱い。成功したバッチだけでは保存しない。 |

---

## 8. セキュリティ

- **API キー**: Script Properties にのみ保持。Logger・エラーメッセージ・レスポンス本文には含めない。
- 本アプリは **トリガー実行のみ** のため、Web 公開・HTTPS の設定は不要（将来 Web UI を足す場合はその時に対応）。

---

## 9. 実装時のファイル構成（案）

- **Code.gs**（または Main.gs）: トリガーで呼ぶエントリポイント、フロー制御、Script Properties 読み込み、画像取得、バッチ分割、並列呼び出し制御、マージ、保存、Logger 出力。
- **Groq.gs**: Groq API 呼び出し（1 バッチ分）、プロンプト組み立て（枚数 N の動的置換）、レスポンスのパース・コードブロック除去、リトライ付きパース。
- **DriveHelper.gs**（任意）: 画像フォルダからの画像一覧取得、リサイズ／圧縮、保存先フォルダへの JSON 保存。
- **Config.gs**（任意）: 定数・既定値（RPM、並列度、バッチサイズ、リトライ回数、GROQ_API_URL / GROQ_MODEL の既定値など）の一元化。

---

## 10. トリガー設定

- ユーザーが GAS の「トリガー」で、実行する関数とスケジュール（例: 日次 9:00）を設定する。
- 実行前に、Script Properties に `GROQ_API_KEY`・`IMAGE_FOLDER_ID`・`OUTPUT_FOLDER_ID` を設定しておく必要がある。
